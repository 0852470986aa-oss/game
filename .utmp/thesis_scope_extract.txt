บทคัดย่อ
วัตถุประสงค์ปริญญานิพนธ์ฉบับนี้เพื่อพัฒนาเกม สมรภูมิรบแห่งดวงดาว Battlefield of the Stars
Online Arena ซึ่งเป็นเกมแนวยิงอวกาศแบบผู้เล่นหลายคนในเวลาจริง (Multiplayer Real-time) บน
ระบบปฏิบัติการ Android ระบบนี้ช่วยให้ผู้เล่นได้รับความบันเทิงและประสบการณ์การแข่งขันที่ลื่นไหล โดย
เน้นการแก้ปัญหาความล่าช้า (Latency) และซิงโครไนซ์ข้อมูลระหว่างผู้เล่นให้ตรงกัน ผู้ใช้งานระบบ
ประกอบด้วย ผู้ดูแลระบบ สมาชิก และผู้ใช้งานทั่วไป ฟังก์ชันหลักของระบบประกอบด้วย การสมัครสมาชิก
และเข้าสู่ระบบ การจับคู่ผู้เล่นเข้าห้องแข่งขัน (Matchmaking) การเลือกสายยานรบ การต่อสู้และใช้
ความสามารถพิเศษแบบเวลาจริง และการบันทึกข้อมูลสถิติ เป็นต้น ระบบนี้ถูกพัฒนาด้วย Unity ร่วมกับ
ภาษา C# โดยใช้ Photon PUN 2 ในการจัดการระบบเครือข่ายผู้เล่นหลายคน และ Firebase สำหรับระบบ
ฐานข้อมูลแบบเรียลไทม์ จากการทดสอบระบบด้วยเทคนิคทดสอบกล่องดำพบว่า ทุกฟังก์ชันสามารถทำงานได้

Authors : Mr. Panpeth Ananram

Supervisor : Assistant Professor Dr. Thawatchai Chomsiri
Abstract
The objective of this thesis is to develop the game Battlefield of the Stars Online Arena,
a real-time multiplayer space shooting game on the Android operating system. This system
provides players with entertainment and a smooth competitive experience by focusing on
resolving latency issues and synchronizing data between players. The system users consist of
administrators, members, and general users. The main functions of the system include
registration and login, matchmaking, spaceship class selection, real-time combat with special
skill usage, and statistical recording. This system was developed using Unity with the C#
programming language, utilizing Photon PUN 2 for multiplayer network management and
Firebase for the real-time database. From testing the system using the black-box testing
technique, it was found that all functions operate correctly.
Keywords: Battlefield of the Stars Online Arena, Unity\nค
กิตติกรรมประกาศ
ปริญญานิพนธ์ฉบับนี้สำเร็จลุล่วงไปได้ด้วยความเรียบร้อย เนื่องจากได้รับความกรุณาอย่างยิ่งจาก
ผู้ช่วยศาสตราจารย์ ดร.ธวัชชัย ชมศิริ อาจารย์ที่ปรึกษาปริญญานิพนธ์ ที่ได้กรุณาสละเวลาอันมีค่าในการให้
คำปรึกษา ชี้แนะแนวทาง ตรวจทาน และแก้ไขข้อบกพร่องต่างๆ ด้วยความเอาใจใส่ในทุกขั้นตอนตลอด
ระยะเวลาของการดำเนินงาน คณะผู้จัดทำขอกราบขอบพระคุณเป็นอย่างสูงไว้ ณ ที่นี้
ขอกราบขอบพระคุณ ผศ.ชุมศักดิ์ สีบุญเรือง ประธานกรรมการสอบ และ ผศ.ดร.ธนันชัย คำเกตุ กรรมการ
สอบปริญญานิพนธ์ ที่ได้กรุณาตรวจสอบ พร้อมทั้งให้ข้อเสนอแนะและคำแนะนำที่มีคุณค่า ซึ่งทำให้ปริญญา
นิพนธ์ฉบับนี้มีความถูกต้องและสมบูรณ์มากยิ่งขึ้น
ขอขอบพระคุณคณาจารย์ประจำสาขาวิชาเทคโนโลยีสารสนเทศ คณะวิทยาการสารสนเทศ มหาวิทยาลัย
มหาสารคาม ทุกท่าน ที่ได้ประสิทธิ์ประสาทวิชาความรู้ และมอบประสบการณ์อันเป็นรากฐานสำคัญที่นำมา
ประยุกต์ใช้ในการพัฒนาระบบเกม "สมรภูมิรบแห่งดวงดาว" จนประสบความสำเร็จ
คุณค่าและประโยชน์อันพึงมีจากปริญญานิพนธ์ฉบับนี้ คณะผู้จัดทำขอมอบเป็นเครื่องบูชาพระคุณ บิดา มารดา
และสมาชิกในครอบครัวทุกท่าน ที่คอยให้ความรัก ความอบอุ่น รวมทั้งให้การสนับสนุนทั้งด้านทุนทรัพย์และ
เป็นกำลังใจอันสำคัญยิ่งเสมอมา ตลอดจนขอขอบคุณเพื่อนๆ นิสิตสาขาวิชาเทคโนโลยีสารสนเทศ ที่คอยให้
ความช่วยเหลือ แลกเปลี่ยนความคิดเห็น และให้กำลังใจซึ่งกันและกันจนปริญญานิพนธ์ฉบับนี้สำเร็จลุล่วงไป

1.1 หลักการและเหตุผล
ปัจจุบันเกมออนไลน์แนวยิงแบบ Multiplayer Real-time ได้รับความนิยมอย่างแพร่หลาย เนื่องจาก
สามารถสร้างความท้าทายและการแข่งขันระหว่างผู้เล่นจริงได้ อย่างไรก็ตาม การพัฒนาเกมในลักษณะ
ดังกล่าวมักประสบปัญหาด้านความล่าช้าในการรับส่งข้อมูลผ่านเครือข่าย (Latency) รวมถึงปัญหาความไม่
ตรงกันของข้อมูลตำแหน่งและการกระทำของผู้เล่น ซึ่งส่งผลให้ประสบการณ์การเล่นเกมลดลงและเกิดความไม่
ยุติธรรมในการแข่งขัน [1] จากปัญหาดังกล่าว โครงการ Battlefield of the Stars Online Arena จึงถูก
พัฒนาขึ้นเพื่อสร้างเกมแนวเครื่องบินยิงกันที่สามารถเล่นออนไลน์พร้อมกันได้แบบเรียลไทม์ โดยมุ่งเน้นให้ผู้
เล่นสามารถแข่งขันกันผ่านเครือข่ายอินเทอร์เน็ตได้อย่างมีเสถียรภาพ และเป็นกรณีศึกษาในการพัฒนาระบบ
เกมออนไลน์ที่มีความซับซ้อน
การแก้ปัญหาในโครงการนี้จะมุ่งเน้นไปที่การออกแบบและพัฒนาระบบเครือข่ายของเกมให้มี
ประสิทธิภาพ โดยใช้หลักการทำงานของระบบ Network Synchronization เพื่อให้ข้อมูลตำแหน่งและการ
กระทำของผู้เล่นทุกคนแสดงผลตรงกันในทุกหน้าจอแบบเรียลไทม์ ลดปัญหาความคลาดเคลื่อนของข้อมูล
ระหว่างผู้เล่น นอกจากนี้ จะมีการพัฒนาระบบจัดการผู้ใช้งาน (Authentication) เพื่อยืนยันตัวตนของผู้เล่น
และใช้ระบบจัดเก็บข้อมูลบนคลาวด์ (Cloud Database) สำหรับบันทึกข้อมูลสถานะและสถิติของผู้เล่นอย่าง
ถาวร รวมถึงการออกแบบระบบจับคู่ผู้เล่น (Matchmaking) และระบบห้องพักคอย (Lobby System) เพื่อให้
ผู้เล่นสามารถสร้างห้อง เข้าร่วมเล่นกับเพื่อน หรือแข่งขันกับผู้เล่นอื่นได้อย่างสะดวกและมีประสิทธิภาพ ซึ่ง
สอดคล้องกับแนวทางการพัฒนาเกมออนไลน์สมัยใหม่ [2]
เมื่อดำเนินการแก้ปัญหาตามแนวทางดังกล่าว เกม Battlefield of the Stars Online Arena จะสามารถ
รองรับการเล่นแบบผู้เล่นหลายคนพร้อมกันได้อย่างราบรื่น ลดปัญหาความล่าช้าและความไม่ตรงกันของข้อมูล
ส่งผลให้ผู้เล่นได้รับประสบการณ์การเล่นที่สมจริงและยุติธรรมมากยิ่งขึ้น นอกจากนี้ ยังช่วยให้ผู้พัฒนาเข้าใจ
การทำงานของระบบเกมออนไลน์ในด้านเครือข่าย การจัดการผู้ใช้งาน และการจัดเก็บข้อมูลบนคลาวด์ ซึ่ง
สามารถนำความรู้และประสบการณ์ที่ได้ไปประยุกต์ใช้ในการพัฒนาเกมหรือระบบซอฟต์แวร์ที่มีความซับซ้อน
ในอนาคตได้\n2
1.2 วัตถุประสงค์
1.2.1 เพื่อพัฒนาระบบเกม Battlefield of the Stars ในรูปแบบ Multiplayer Real-time ด้วย Unity
Game Engine ที่ผู้เล่นสามารถแข่งขันกันได้พร้อมกันผ่านระบบเครือข่ายอินเทอร์เน็ต
1.2.2 เพื่อศึกษากระบวนการและการทำงานของระบบ Network Synchronization ในการทำให้ข้อมูล
ตำแหน่งและการกระทำของผู้เล่นตรงกันในทุกหน้าจอ
1.2.3 เพื่อพัฒนาระบบจัดการผู้ใช้งาน (Authentication) และระบบจัดเก็บข้อมูลบนคลาวด์ (Firebase)
สำหรับบันทึกสถานะและสถิติของผู้เล่นได้อย่างถาวร
1.2.4 เพื่อพัฒนาระบบจับคู่ผู้เล่น (Matchmaking) และระบบห้องพักคอย (Lobby System) ที่รองรับ
การสร้างห้องและการเข้าร่วมเล่นกับเพื่อนได้

1.3.3 สว่ นของระบบทางเทคนิค (System Scope)\n10
ขอบเขตในส่วนนี้มุ่งเน้นการพัฒนาระบบสถาปัตยกรรมเครือข่ายและการจัดการข้อมูลบนระบบคลาวด์
เพื่อให้ตัวเกมสามารถรองรับการเล่นแบบผู้เล่นหลายคน (Multiplayer) ได้อย่างมีประสิทธิภาพและมีความ
ปลอดภัยของข้อมูลสูง โดยมีรายละเอียดดังนี้:
1.3.3.1 ระบบเครือข่ายและการสื่อสาร (Networking with Photon PUN 2)
การจัดการระบบปฏิสัมพันธ์แบบเวลาจริง (Real-time Interaction) เพื่อให้ผู้เล่นสามารถตอบโต้กัน

1.3.3.1.1 ระบบห้องพักคอยและการจับคู่ (Lobby & Matchmaking System)พัฒนา
ระบบให้ผู้เล่นสามารถสร้างห้องแข่งขัน (Create Room) โดยระบุเกมจะระบุเลขห้องให้ และระบบการค้นหา
เพื่อเข้าร่วมห้อง (Join Room) ผ่านเลขห้องที่ถูกต้อง การจัดการสถานะความพร้อมของผู้เล่น (Ready
Status) ภายในห้องพักคอยก่อนเริ่มการแข่งขัน
1.3.3.1.2 การประสานข้อมูลตำแหน่งและสถานะ (Network Synchronization) ใช้เทคนิค
Dead Reckoning และ Interpolation ผ่าน Component PhotonTransformView เพื่อทำการซิงโครไนซ์
ตำแหน่ง (Position) และการหมุน (Rotation) ของยานอวกาศให้มีความต่อเนื่องบนหน้าจอของผู้เล่นทุกคน
การซิงโครไนซ์สถานะพลังชีวิต (Health Points) และสถานะความ เสียหายระหว่างเครื่องผู้เล่นทุก
คนในห้องแบบวินาทีต่อวินาที

เหตุการณ์สำคัญท ี่ เกิดขึ้นเพียงครั้งเดียวแต่ต้องการความแม่นยำสูง เช่น การส่งคำสั่งยิงกระสุน, การคำนวณ
ดาเมจเมื่อกระสุนชนเป้าหมาย, และการส่งสถานะผิดปกติ (Stun) ไปยังเครื่องคู่ต่อสู้

ด้านความปลอดภัยของบัญชีผู้ใช้งานและการจัดเก็บข้อมูลความก้าวหน้าของผู้เล่น

รักษาความปลอดภัยของข้อมูลผู้ใช้

ของผู้เล่นตลอดเวลาแบบ Real-time เพื่อระบุสถานะสิ้นสุดเกม
1. เงื่อนไขการชนะ (Victory): เมื่อผู้เล่นสามารถลดค่าพลังชีวิต (HP) ของยานฝ่ายตรงข้าม
จนเหลือ 0 ระบบจะหยุดการเล่นและแสดงหน้าจอ WIN ทันที
2. เงื่อนไขการแพ้ (Defeat): เมื่อค่าพลังชีวิต (HP) ของยานผู้เล่นเหลือ 0 จะถือว่าพ่ายแพ้
ในรอบนั้น ระบบจะแสดงหน้าจอ LOSE
3. การตัดการเชื่อมต่อ (Disconnection) หากผู้เล่นคนใดคนหนึ่งออกจากห้อง (Leave
Room) ก่อนการแข่งขันจบลง ระบบจะปรับให้ผู้เล่นที่ยังอยู่เป็นฝ่ายชนะโดยอัตโนมัติ\n12

2. โบนัสพิเศษ: ระบบสามารถคำนวณเหรียญเพิ่มเติมจากประสิทธิภาพการเล่นเช่น ความ

2.1.1 Unity Game Engine
Unity Game Engine [3] เป็นแพลตฟอร์มพัฒนาเกมแบบเรียลไทม์ ที่ใช้สร้างเกม 2D และ 3D,
รวมถึงระบบอินเทอร์แอ็กทีฟต่าง ๆ, รองรับการเขียนสคริปต์ด้วยภาษา C# และสามารถนำไปใช้งานบนหลาย
แพลตฟอร์มได้ Unity ยังมีระบบจัดการวัตถุภายในเกม (Game Objects), ระบบฟิสิกส์, ระบบเรนเดอร์ และ
สามารถติดตั้งแพ็กเกจเสริมสำหรับระบบ Multiplayer ได้อย่างยืดหยุ่น
2.1.2 Photon Unity Networking 2 (PUN 2)
Photon Unity Networking 2 (PUN 2) [4] คือ SDK เครือข่ายที่ช่วยให้เกม Unity สามารถ
สื่อสารระหว่างผู้เล่นแบบเรียลไทม์ได้อย่างราบรื่น โดยจัดการทั้งการเชื่อมต่อเซิร์ฟเวอร์ การจับคู่ผู้เล่น
(Matchmaking) และการซิงโครไนซ์ข้อมูลสถานะผู้เล่นซึ่งเป็นหัวใจสำคัญของเกม Multiplayer ออนไลน์
PUN ใช้ระบบ Realtime App Id เพื่อระบุการเชื่อมต่อเกมและทำงานผ่านโครงสร้าง Photon Cloud ที่
กระจายอยู่ทั่วโลกเพื่อให้การเชื่อมต่อเสถียรและมี Latency ตำ่
2.1.3 Firebase
Firebase [5] เป็นแพลตฟอร์มสำหรับพัฒนาแอปพลิเคชันจาก Google ที่มีเครื่องมือ Backend-
as-a-Service (BaaS) ครบวงจร ในโครงงานนี้เลือกใช้บริการ Firebase Authentication สำหรับจัดการระบบ
ยืนยันตัวตนผู้เล่นผ่าน Google Account และ Firebase Realtime Database ซึ่งเป็นฐานข้อมูล NoSQL
บนคลาวด์สำหรับการจัดเก็บข้อมูลผู้เล่น (เช่น เงินในเกม, ยานที่ครอบครอง) และสถิติการเล่นแบบเรียลไทม์ที่
มีความปลอดภัยและสามารถเข้าถึงได้จากทุกอุปกรณ์
2.1.4 Visual Studio / Visual Studio Code
Visual Studio และ Visual Studio Code [6] เป็นเครื่องมือสำหรับเขียนโค้ดที่รองรับภาษา C#
ซึ่งใช้ร่วมกับ Unity ในการพัฒนาเกม โดยทั้งสองโปรแกรมสามารถเชื่อมต่อกับระบบ GitHub เพื่อจัดการ
เวอร์ชันของโค้ดได้อย่างมีประสิทธิภาพ Visual Studio มีระบบจัดการ Git และ GitHub ในตัว ส่วน VS Code
มีส่วนขยายและสนับสนุนการใช้งานกับ Git, GitHub, และระบบจัดการเวอร์ชันอื่น ๆเพื่อเพิ่มความสะดวกใน
การเขียนและดีบักโค้ดโปรเจกต์เกมของนักพัฒนา\n16
2.1.5 Git / GitHub
GitHub [7] เป็นระบบควบคุมเวอร์ชันแบบกระจาย (Distributed Version Control System) ที่ใช้
จัดการการเปลี่ยนแปลงของซอร์สโค้ดในโปรเจกต์พัฒนาเกมหรือซอฟต์แวร์ มันช่วยติดตามการแก้ไขต่าง ๆ
ย้อนกลับไปยังสถานะก่อนหน้า และสนับสนุนการทำงานแบบทีมได้อย่างมีระบบ GitHub เป็นบริการบนเว็บ
สำหรับเก็บ repository ของ Git ที่ทำหน้าที่เป็นที่เก็บและแชร์ซอร์สโค้ด รวมทั้งรองรับระบบ issues, pull
requests และ collaboration workflow ที่เหมาะกับการพัฒนาโครงงานเป็นทีมด้านเกมและซอฟต์แวร์
2.1.6 ภาษา C#
C Sharp [8] ภาษาโปรแกรมหลักที่ใช้ในการเขียนชุดคำสั่ง (Scripting) สำหรับควบคุมการทำงานของ
เกมใน Unity ตั้งแต่ระบบฟิสิกส์ การควบคุมยานอวกาศ ไปจนถึงการเชื่อมต่อข้อมูลกับ Photon PUN 2 และ
Firebase
2.1.7 Adobe Photoshop
Adobe Photoshop [9] โปรแกรมตกแต่งภาพกราฟิกที่ใช้สำหรับการออกแบบและจัดเตรียมสินทรัพย์
ภายในเกม (Game Assets) ได้แก่ การตัดต่อภาพยานอวกาศ, การสร้างฉากหลัง (Background), และการ
ออกแบบส่วนติดต่อผู้ใช้งาน (User Interface) เช่น ปุ่มกดและแถบสถานะ
2.1.8 Draw.io
Draw.io [10] เครื่องมือสำหรับสร้างแผนภาพออนไลน์ที่ใช้ในการออกแบบผังงานระบบ (Flowchart),
แผนภาพ Use Case และผังโครงสร้างฐานข้อมูล เพื่อวางแผนขั้นตอนการทำงานของระบบให้ชัดเจนก่อนเริ่ม
ดำเนินการพัฒนา
2.1.9 ขั้นตอนการพัฒนาระบบ
ภาพประภกาอพบปทรี่ ะ2ก. อ1บ วทงี่ จ2ร.1ก าวรงพจัฒรกนาารรพะัฒบนบา ระบบ\n17
2.1.9.1 การวิเคราะห์ปัญหาและความต้องการของระบบ
ในขั้นตอนนี้เป็นการศึกษาและวิเคราะห์ปัญหาจากการพัฒนาเกมออนไลน์แนวยิงแบบ Multiplayer
Real-time ซึ่งมักพบปัญหาด้านความล่าช้าในการส่งข้อมูล (Latency) และความไม่ตรงกันของข้อมูลตำแหน่ง
จึงนำมาสู่การกำหนดความต้องการของระบบ ดังนี้:
ความต้องการด้านระบบเครือข่าย: ระบบต้องรองรับการเล่นพร้อมกันแบบเรียลไทม์ และมีการ
•
ซิงโครไนซ์ข้อมูลตำแหน่ง สถานะผู้เล่น และการกระทำของยานอวกาศได้อย่างแม่นยำ
ความต้องการด้านการจัดการข้อมูล: ระบบต้องมีการยืนยันตัวตนผู้เล่น และสามารถจัดเก็บ
•
ข้อมูลสถิติการเล่น (ชนะ/แพ้) รวมถึงสถานะผู้เล่นบนระบบคลาวด์ (Cloud Database) ได้อย่าง
ถาวรและปลอดภัย
ความต้องการด้านผู้ใช้งาน: ตัวเกมต้องควบคุมได้ง่ายและเหมาะสมกับอุปกรณ์พกพา (Android)
•
มีระบบจับคู่ผู้เล่น (Matchmaking) และระบบห้องพักคอย (Lobby) เพื่อรองรับการเล่นกับ
เพื่อน
2.1.9.2 การออกแบบระบบ
หลังจากทราบความต้องการของระบบ ได้นำมาออกแบบสถาปัตยกรรมและส่วนประกอบต่างๆ
ภายในเกม ได้แก่:
การออกแบบระบบเครือข่าย: ออกแบบโครงสร้างแบบ Client-Server โดยใช้ Photon Cloud
•
ในการจัดการห้องพักคอย และใช้ระบบ Master Client Authority จัดการเหตุการณ์กลางของ
เกมเพื่อป้องกันข้อมูลไม่ตรงกัน (Desync) ระหว่างผู้เล่น
การออกแบบฐานข้อมูล: ออกแบบโครงสร้างฐานข้อมูลแบบ NoSQL ผ่าน Firebase Realtime
•
Database สำหรับเก็บข้อมูลโปรไฟล์ผู้ใช้ (User Profile), สถิติเกม (Game Statistics) และ
ระบบคลังแสง (Inventory)
การออกแบบส่วนติดต่อผู้ใช้งานและกราฟิก: ออกแบบผังงานระบบ (Flowchart) ด้วย Draw.io
•
และจัดเตรียมสินทรัพย์ภายในเกม (Game Assets) เช่น ยานอวกาศ รวมถึงออกแบบหน้า
จอแสดงผลขณะเล่น (HUD) อย่าง Virtual Joystick และปุ่มสกิล ด้วยโปรแกรม Adobe
Photoshop
การออกแบบกลไกและสมดุลเกม (Game Mechanics): ออกแบบประเภทยานอวกาศให้มี
•
คุณสมบัติแตกต่างกัน 3 สาย (สายสมดุล, สายความเร็ว, สายป้องกัน) และออกแบบแผนที่การรบ
3 รูปแบบที่มีอุปสรรคและกลไกแวดล้อมต่างกัน
2.1.9.3 การพัฒนาระบบ
เป็นขั้นตอนการลงมือเขียนโปรแกรมและสร้างเกมตามที่ได้ออกแบบไว้ โดยใช้เครื่องมือและเทคโนโลยี
ดังนี้:\n18
การพัฒนาเอนจินเกมและสคริปต์ (Game Engine & Scripting): สร้างสภาพแวดล้อมแบบ 2D และ
•
ระบบฟิสิกส์ภายในเกมด้วย Unity Game Engine และพัฒนาชุดคำสั่งควบคุมตรรกะของเกมด้วย
ภาษา C# โดยใช้เครื่องมือ Visual Studio หรือ Visual Studio Code
การพัฒนาระบบเครือข่าย (Network Development): นำ SDK ของ Photon Unity Networking 2
•
(PUN 2) มาพัฒนาเพื่อจัดการการเชื่อมต่อ จับคู่ผู้เล่น และใช้เทคนิคอย่าง Dead Reckoning และ
RPC (Remote Procedure Calls) ในการส่งคำสั่งและสถานะการโจมตีข้ามเครือข่าย
การเชื่อมต่อฐานข้อมูล: ติดตั้งและตั้งค่า Firebase SDK เพื่อใช้งาน Authentication สำหรับผูกบัญชี
•
Google Sign-In และเขียนชุดคำสั่งอัปเดตผลการแข่งขันและเหรียญรางวัลส่งไปยังฐานข้อมูลทันที
เมื่อจบการรบ
การจัดการเวอร์ชัน (Version Control): ใช้ Git และ GitHub ในการติดตามและจัดการการ
•
เปลี่ยนแปลงของซอร์สโค้ด เพื่อความสะดวกในการทำงานร่วมกันภายในทีม
2.1.9.4 การทดสอบระบบ
เมื่อพัฒนาระบบเบื้องต้นเสร็จสิ้น ได้นำตัวเกมมาทดสอบเพื่อหาข้อผิดพลาดและปรับปรุง
ประสิทธิภาพการทำงาน:
การทดสอบบนอุปกรณ์จริง: นำเกมไปติดตั้งและทดสอบบนอุปกรณ์เคลื่อนที่ระบบปฏิบัติการ
•
Android 15 (เช่น สมาร์ตโฟน POCO F6) เพื่อทดสอบการประมวลผล ความลื่นไหลในการ
ควบคุม และการแสดงผล UI บนหน้าจอ
การทดสอบระบบ Multiplayer แบบเรียลไทม์: ทดสอบความถูกต้องในการซิงโครไนซ์ข้อมูล
•
ตำแหน่ง และการลดค่าพลังชีวิต (Health Points) ระหว่างเครื่องผู้เล่น ตลอดจนจำลองการเกิด
ปัญหากรณีมีผู้เล่นหลุดการเชื่อมต่อกลางคัน (Disconnection)
การทดสอบความถูกต้องของข้อมูล (Database Testing): ทดสอบเงื่อนไขแพ้-ชนะ และ
•
ตรวจสอบว่าระบบคำนวณเหรียญแร่อาสโทรเนียมและบันทึกสถิติ (Win/Lose) กลับเข้าสู่
Firebase Database ได้อย่างถูกต้องแม่นยำ
2.1.9.5 การดูแลระบบ
เป็นขั้นตอนการบำรุงรักษาหลังจากเกมเปิดให้สามารถเข้าเล่นได้:
การจัดการเซิร์ฟเวอร์และฐานข้อมูล: ตรวจสอบและติดตามปริมาณการใช้งานแบนด์วิดท์ของ
•
Photon Cloud และโควตาการใช้งานของ Firebase Database ไม่ให้เกินขีดจำกัด เพื่อให้
เซิร์ฟเวอร์ทำงานได้อย่างมีเสถียรภาพ
การปรับสมดุลเกม (Game Balancing): ตรวจสอบสถิติและผลลัพธ์การแข่งขันของผู้เล่นอย่าง
•
ต่อเนื่อง เพื่อนำมาปรับปรุงค่าสถานะพื้นฐานของยานอวกาศแต่ละรุ่น (พลังชีวิต, ความเร็ว, อัตรา
การยิง) รวมถึงระยะเวลาคูลดาวน์ของสกิลต่างๆ เพื่อสร้างความยุติธรรมในการแข่งขัน\n19
การแก้ไขข้อผิดพลาด (Bug Fixing): แก้ไขปัญหาที่พบเจอจากการใช้งานของผู้เล่นจริง เช่น
•
ข้อบกพร่องในระบบฟิสิกส์การชน (Collision) และการอัปเดตแพตช์เพื่อให้ระบบรองรับกับ
ระบบปฏิบัติการหรืออุปกรณ์รุ่นใหม่ๆ ในอนาคต

2.2.1 ระบบที่ 1 Starblast
ภาพประกอบที่ 2.2 เกม Starblast
Starblast [11] รายเอียด: เป็นเกมยานอวกาศยิงต่อสู้แบบออนไลน์ (Arcade Space Shooter) ที่
เล่นผ่านเว็บเบราว์เซอร์ โดยเน้นการเล่นแบบ Multiplayer Real-time สไตล์ .io ซึ่งผู้เล่นต้องเก็บเพชร
เพื่ออัปเกรดยานและต่อสู้กับผู้เล่นอื่นในแผนที่เดียวกัน
- ข้อดี:
1. Accessibility: เข้าถึงง่าย สามารถเล่นผ่านเว็บเบราว์เซอร์ได้ทันทีโดยไม่ต้อง
ติดตั้งโปรแกรม (Client-free)
2. Smooth Gameplay: ระบบการควบคุมยานมีความลื่นไหล ฟิสิกส์การชนและ
การเคลื่อนที่ทำได้สมจริงในระดับ 2D
3. Team Mode: มีระบบแบ่งฝ่าย (Team Mode) ที่ชัดเจน ทำให้ผู้เล่นเกิดความ
ร่วมมือกันภายในทีม
- ข้อด้อย:
1. Lack of Persistence: ในโหมดการเล่นทั่วไป เมื่อจบเกมหรือปิดเบราว์เซอร์
ข้อมูลการอัปเกรดยานจะหายไป ไม่มีการบันทึกสถานะถาวรลงฐานข้อมูล (Cloud
Database)
2. Matchmaking Balance: ระบบจับคู่บางครั้งนำผู้เล่นใหม่ไปรวมกับผู้เล่นที่มี
เลเวลยานสูงมาก ทำให้เกิดความเสียเปรียบในการแข่งขันทันทีที่เริ่มเกม\n20
3. Network Jitter: ในช่วงที่มีผู้เล่นจำนวนมาก อาจเกิดอาการกระตุก (Lag) หรือ ตำแหน่ง
ยานไม่ตรงกันเล็กน้อย (Desync) ซึ่งเป็นปัญหาของการจัดการ Network Synchronization

ออกเป็น 2 ด้าน ดังนี้
5.3.1 ข้อเสนอแนะสำหรับการพัฒนาระบบด้านเทคนิค
1. การขยายแพลตฟอร์ม (Cross-Platform): ปัจจุบันระบบรองรับเฉพาะระบบปฏิบัติการแอน
ดรอยด์ (Android) ในอนาคตควรปรับปรุงให้รองรับระบบปฏิบัติการ iOS และระบบ
คอมพิวเตอร์ (PC) เพื่อเพิ่มฐานผู้เล่น
2. การปรับแต่งประสิทธิภาพ (Optimization): ควรเพิ่มการปรับแต่ง กราฟิก และฟิสิกส์ภายใน
เกม เพื่อให้สามารถนำไปเล่นบนอุปกรณ์สมาร์ตโฟนรุ่นเก่า หรือสเปกต่ำได้อย่างราบรื่นยิ่งขึ้น
3. ระบบป้องกันการโกง (Anti-Cheat): ในการพัฒนาขั้นถัดไป ควรเพิ่มระบบตรวจสอบข้อมูล
ฝั่งเซิร์ฟเวอร์ (Server-side Validation) เพื่อป้องกันการดัดแปลงข้อมูลการต่อสู้หรือการใช้
โปรแกรมโกงเกม
5.3.2 ข้อเสนอแนะสำหรับการพัฒนาเกมเพลย์และประสบการณ์ผู้เล่น
1. การเพิ่มเนื้อหาภายในเกม (Content Expansion): ควรเพิ่มรูปแบบยานรบใหม่ๆ ระบบ
ปรับแต่งตกแต่งยาน (Skins/Customization) และเพิ่มแผนที่การรบที่มีกลไกใหม่ๆ เพื่อรักษา
ความสนใจของผู้เล่นในระยะยาว
2. ระบบการแข่งขันและจัดอันดับ (Ranked Match & Leaderboard): ควรพัฒนาระบบการจัด
อันดับฤดูกาล (Seasonal Ranking) เพื่อสร้างแรงจูงใจในการแข่งขันของผู้เล่น และรองรับการ
เติบโตไปสู่การแข่งขันระดับ E-sports
3. ระบบการสื่อสารระหว่างผู้เล่น (Communication System): ควรเพิ่มระบบการสื่อสารด้วย
เสียง (Voice Chat) หรือข้อความด่วน (Quick Chat) ภายในห้องต่อสู้ เพื่อให้ผู้เล่นในทีม
สามารถวางแผนและสื่อสารกันได้สะดวกยิ่งขึ้น\n94

ภาคผนวก ข
คู่มือการใช้งานระบบ
ภาคผนวกนี้อธิบายขั้นตอนการใช้งานเกมสมรภูมิรบแห่งดวงดาว ตั้งแต่การเข้าสู่ระบบ การใช้งานเมนู
หลัก การเข้าร่วมห้องแข่งขัน การควบคุมยานอวกาศภายในเกม ตลอดจนการแสดงผลการแข่งขันหลังจบเกม
1. การเข้าสู่ระบบ
เมื่อผู้ใช้งานเปิดเกม ระบบจะแสดงหน้าจอเข้าสู่ระบบ โดยผู้ใช้งานสามารถเข้าสู่ระบบด้วยบัญชี Google
และ Guest เพื่อยืนยันตัวตนก่อนเข้าใช้งานระบบ
ภาพประกอบที่ ข.1 หน้าจอเข้าสู่ระบบ
ขั้นตอนการเข้าสู่ระบบมีดังนี้
1. เปิดแอปพลิเคชันเกมสมรภูมิรบแห่งดวงดาว
2. กดปุ่ม Sign in with Google
3. เลือกบัญชี Google ที่ต้องการใช้งาน
4. ระบบตรวจสอบข้อมูลผู้ใช้งาน
5. เมื่อเข้าสู่ระบบสำเร็จ ระบบจะแสดงหน้าเมนูหลัก\n97
2. หน้าจอเมนูหลัก
เม่ือเขา้ ส่รู ะบบสา เรจ็ ผใู้ ชง้ านจะเขา้ ส่หู นา้ เมนหู ลกั ซ่งึ เป็นหนา้ สา หรบั เลือกใชง้ านฟังกช์ นั ต่าง ๆ ของเกม เช่น การเรม่ิ
เล่นเกม การจดั การยานหรืออปุ กรณ ์และการเขา้ ส่รู ะบบหอ้ งแข่งขนั ผใู้ ชง้ านสามารถเลือกเมนทู ่ตี อ้ งการไดโ้ดยกดป่มุ บน
หนา้ จอ
ภาพประกอบที่ ข.2 หน้าจอเมนูหลัก
3. การเลือกยานและสกิล
ก่อนเข้าสู่การแข่งขัน ผู้เล่นสามารถเลือกยานอวกาศหรืออุปกรณ์ที่ต้องการใช้ในการแข่งขันได้ โดยระบบจะ
แสดงรายการยานหรืออุปกรณ์ที่ผู้เล่นสามารถเลือกใช้งานได้
ภาพประกอบที่ ข.3 หน้าจอการเลือกยานและสกิล
ขั้นตอนการเลือกยานมีดังนี้
1. เข้าสู่เมนูเลือกยาน\n98
2. เลือกยานอวกาศที่ต้องการใช้งาน
3. เลือกอุปกรณ์หรือความสามารถที่ต้องการ
4. กดยืนยันการเลือก
5. ระบบบันทึกยานและอุปกรณ์ที่เลือกไว้สำหรับการแข่งขัน
4. การเข้าสู่ห้องแข่งขัน
เมื่อผู้เล่นต้องการเล่น ให้เลือกเมนู Create/Join Room ระบบจะเชื่อมต่อกับเซิร์ฟเวอร์และแสดงหน้าห้อง
แข่งขัน
ภาพประกอบที่ ข.4 หน้าจอการสร้างห้องหรือค้นหาห้อง
ผู้เล่นสามารถใช้งานได้ 2 รูปแบบ ได้แก่
4.1. การสร้างห้อง (Create Room)
ผู้เล่นสามารถสร้างห้องแข่งขันใหม่เพื่อรอผู้เล่นอีกคนเข้าร่วม โดยมีขั้นตอนดังนี้
1. กดปุ่ม Create Room
2. ระบบสร้างห้องแข่งขัน
3. ผู้เล่นรอผู้เล่นอีกคนเข้าร่วมห้อง
4. เมื่อมีผู้เล่นครบ ระบบจะแสดงสถานะของผู้เล่นภายในห้อง\n99
4.2. การเข้าร่วมห้อง (Join Room)
ผู้เล่นสามารถเข้าร่วมห้องที่ถูกสร้างไว้แล้ว โดยมีขั้นตอนดังนี้
1. กดปุ่ม Join Room
2. ระบบค้นหาห้องที่สามารถเข้าร่วมได้
3. เมื่อพบห้อง ระบบจะนำผู้เล่นเข้าสู่ห้องแข่งขัน
4. ระบบแสดงข้อมูลผู้เล่นทั้งสองฝ่าย
5. การควบคุมยานอวกาศ
เมื่อเข้าสู่การแข่งขัน ผู้เล่นสามารถควบคุมยานอวกาศผ่านปุ่มควบคุมที่แสดงบนหน้าจอของโทรศัพท์มือถือ
ภาพประกอบที่ ข. 5 หน้าจอการแข่งขัน
ส่วนควบคุมหลักประกอบด้วย
1. ปุ่มควบคุมทิศทาง ใช้สำหรับเคลื่อนที่ยานอวกาศไปยังทิศทางต่าง ๆ
2. ปุ่มยิง ใช้สำหรับยิงกระสุนโจมตีฝ่ายตรงข้าม
3. ปุ่มใช้ความสามารถพิเศษ ใช้สำหรับใช้งานสกิลหรืออุปกรณ์พิเศษที่ผู้เล่นเลือกไว้
4. แถบพลังชีวิต (HP) ใช้แสดงค่าพลังชีวิตของผู้เล่นและฝ่ายตรงข้าม\n100
